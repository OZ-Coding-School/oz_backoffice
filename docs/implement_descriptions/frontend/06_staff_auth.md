## 배경
FE-1(인증 화면)의 마지막 PR이다(F20). 운영진 화면 두 가지를 만든다.
- **로그인 (`/staff/login`):** 회사 Google 계정으로 로그인한다.
- **최초 정보 입력 (`/staff/registration`):** Google로 처음 로그인한 운영진이 소속·담당을 입력한다. 신청한 뒤에는 승인 대기·반려 상태를 이 화면에서 본다.

구현 전에 Figma에 운영진 화면 5개(로그인, Google 오류, 정보 입력, 승인 대기, 반려)의 태블릿·모바일 뷰 10개를 먼저 그렸다(F21).

PR을 연 뒤 테스트하다가 담당 선택 방식이 바뀌었다. 직위에 따라 과정 여러 개 또는 기수 하나를 고르고, 조직은 부서·팀으로 나뉜다(A62). 백엔드를 먼저 바꾸고(#79, #80), 정보 입력 화면을 다시 그린 뒤(처음·과정·조교·담당 없음 × 3크기) 다시 구현했다(F26).

**정보 입력 화면** (`staff-registration-page.tsx`)
- **입력:** 부서 → 팀 → 직위·고용 형태 → 담당 순서로 칸이 나타난다(F26).
  - 과정 담당 직위(COURSE)는 소속 팀 과정을 드롭다운에서 골라 목록에 추가한다(운영 매니저). 추가한 과정은 드롭다운에서 빠지고 X로 뺀다. 처음에는 체크 목록이었는데, 과정이 많아지면 길어져서 사용자 결정으로 바꿨다.
  - 조교(COHORT)는 과정 → 기수를 하나 고른다. 승인된 조교가 없는 기수만 보인다(A63).
  - 팀이 없거나(부서 직속) 담당 방식이 없는 직위면 담당 섹션이 없다.
  - 앞 칸을 바꾸면 뒤 칸 값을 비운다.
- **승인 대기:** 신청 요약(부서·팀·직위·고용 형태·담당)을 보여 준다. '신청 내용 수정'과 '새로고침'이 있다.
- **반려:** 사유를 보여 주고, 이전 입력을 채운 폼으로 다시 신청한다.

## 주요 결정 (사용자 결정, F25·F26)
- 담당은 **0개도 허용**한다(백엔드 규칙).
- ~~부서는 '상위 › 하위' 경로로 보여 준다~~ → 부서·팀 두 칸(A62·F26).
- 승인 대기의 '새로고침'은 **알림 없이 다시 조회만** 한다. 승인됐으면 운영진 홈으로, 반려됐으면 반려 화면으로 바뀐다.
- 모바일은 칸을 세로로 쌓는다. 데스크톱·태블릿은 두 칸씩 놓는다.
- 칸은 앞 칸을 고르면 나타나고, 앞 칸을 바꾸면 뒤 칸 값을 비운다(F26).

## 구현 세부
- **역할은 고르지 않는다:** 직위 담당 방식으로 정해진다(COURSE → 운영 매니저, COHORT → 조교).
- **반려 후 다시 신청:** 이전 신청의 팀이 없으면 "선택 안 함"으로, 조교 기수는 그 기수의 과정까지 채운다.
- **팀에 과정이 없을 때:** "소속 팀이 담당하는 과정이 아직 없어요. 담당 없이 신청할 수 있어요."
- **로그인 후 경로:** Google 로그인 성공 후 백엔드는 `/`로 돌려보낸다. 가드가 계정 종류·승인 상태로 정보 입력 화면 또는 운영진 홈(`/admin`)으로 보낸다.
- **Google 아이콘:** "G" 로고는 Google 브랜드 4색 SVG를 그대로 넣었다(토큰 색이 아님).

## 발견한 문제와 해결
- **Figma 모바일 정보 입력:** 부서·직위를 세로로 바꾸자 칸이 겹쳤고, 담당 줄의 대상 칸이 사라졌다. 셀렉트가 가로 배치에서 받은 '세로 채우기(FILL)'가 남아 있었기 때문이라 내용 높이(HUG)로 고쳤다.
- **태블릿 담당 줄:** 400 폭에서는 대상 이름이 두 줄로 꺾였다. 태블릿도 모바일처럼 두 줄 배치로 바꿨다.
