## 배경
F28 순서의 마지막 작업이다. 신청 상세에서 [신청 변경]으로 들어가 한 페이지에서 일정과 신청 내용을 바꾼다. 변경은 기존 신청을 고치는 것이 아니라, 기존 신청을 취소하고 같은 대상(멘토·종류 그대로)의 새 신청을 만드는 것이다(A44, `replaced_request_id`).

구현 전에 Figma에 변경 페이지를 1440·768·390으로 그렸다(F21). 위치는 `Member - 수강생 › Column / 신청 변경 (FE-4b)`이다. FE-4a 상세 화면 6개에도 [신청 변경] 버튼을 더했다.

## 구현 내용

| 경로 | 역할 |
| --- | --- |
| `src/routes/_member/mentoring/requests/$requestId_.change.tsx` | `/mentoring/requests/{id}/change` (상세와 겹치지 않는 형제 경로). 수강생만 |
| `src/features/requests/api.ts` | `useChangeRequest`: 새 신청을 상세 캐시에 넣고 기존 상세·목록·계좌·가능 시간을 무효화한다 |
| `components/change-request-page.tsx` | 고정된 멘토·종류, ① 일정(FE-3a 일정 단계 재사용), ② 신청 내용(FE-3a 내용 단계 재사용), 아래 막대([취소]·[변경 저장]), 승인된 신청 경고, 바꿀 수 없을 때 안내 |
| `components/request-detail-page.tsx` | [신청 변경] 버튼(취소와 같은 조건). 안내 문구를 '바꾸거나 취소할 수 있어요'로 바꿨다 |
| `src/features/requests/messages.ts` | 변경 오류: 마감 지남·이미 처리됨·신청자 아님 + 신청 오류 문구 |

### 화면 규칙 (F32)
- [신청 변경]은 취소와 같은 조건일 때 보인다.
  - 신청자만 볼 수 있다.
  - 승인 대기는 언제든, 승인된 신청은 시작 `min_lead_hours` 전까지다.
  - 변경 페이지로 직접 들어와도 같은 조건을 보고, 조건이 안 맞으면 '이 신청은 바꿀 수 없어요'를 보여 준다.
- 기존 값으로 채운다: 진행 시간, 아직 지나지 않은 희망 일시, 주제, 상세 내용. 임시 저장은 하지 않는다.
- 진행 시간 선택지는 '남은 시간 + 이 신청의 차감 예정·차감 시간'까지 넓힌다. 기존 신청을 먼저 취소해 그 시간을 돌려받기 때문이다.
- 승인된 신청이면 위쪽에 '저장하면 확정된 세션이 취소돼요'를 띄운다. 지금 잡힌 시간은 신청 가능 시간에 나오지 않아 다시 고를 수 없다.
- 저장하면 새 신청 상세로 가서(`replace`) '신청을 바꿨어요' 알림을 띄운다.

## 주요 결정 (사용자 결정, F32)
- 백엔드를 따라 승인된 신청도 마감 전까지 바꿀 수 있다.
- 주소는 `/mentoring/requests/{id}/change`이다.
- 저장하면 새 신청 상세로 가고 알림을 띄운다.
- 임시 저장은 하지 않는다.
- 승인된 신청을 바꿀 때 지금 잡힌 세션 시간은 고를 수 없고 다른 시간만 고른다.

## 발견한 문제와 해결
- 상세 경로 아래에 `$requestId.change`로 두면 상세 화면에 `Outlet`이 없어 변경 화면이 보이지 않는다. 그래서 `$requestId_.change`(중첩하지 않는 형제 경로)로 만들었다.
