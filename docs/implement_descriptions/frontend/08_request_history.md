### 화면 규칙 (F29)
- 탭 건수는 첫 페이지 응답의 `counts`(필터와 무관)로 센다. 반려·취소 탭은 `status=REJECTED&status=CANCELED`로 조회한다.
- 차감 상태는 응답 `balance`로 보여 준다. 표시는 차감 예정 N / N 차감 / 시간 돌려받음이고, 팀 신청은 앞에 '팀 계좌'를 붙인다.
- 취소 안내 꼬리는 `(11/06 12:30 본인 취소)`다.
  - 주체 표시: 본인 / 신청자 이름 / 멘토 / 운영진 / 자동
  - A66 이전 행처럼 주체가 없으면 시각만 보여 준다.
- 취소할 수 있는 사람은 신청자다. 1:1은 본인, 팀 신청은 신청한 팀원이다. 다른 팀원은 보기만 한다.
  - 승인 대기: 언제든 취소할 수 있다.
  - 승인: 확정 세션 시작 `min_lead_hours` 전까지 취소할 수 있다(같은 시각 포함). 값은 기수 설정 요약에서 받는다.
  - 마감이 지나면 버튼 대신 "취소 마감이 지났어요. 운영진에게 문의해 주세요."를 보여 준다.
  - 최종 판정은 서버가 한다. `cancel_deadline_passed`는 창 안에 알리고, `request_not_cancelable`이면 다시 조회한다.
- 반려·취소된 신청의 상세는 사유 상자만 보여 주고 시간·취소 영역을 숨긴다.
- [신청 변경]은 FE-4b에서 추가한다.

## 주요 결정 (사용자 결정, F29)
- 탭은 시안대로 4개이고 건수를 붙인다. 백엔드 보완 A67을 먼저 했다.
- 목록은 무한 스크롤로 불러온다.
- 승인된 신청도 마감 전까지 상세에서 취소할 수 있다.
- [신청 변경] 버튼은 FE-4b에서 넣는다.
- 메뉴에 배지를 넣지 않는다.

## 발견한 문제와 해결
- `renderRoute`는 `setDefaultOptions({ retry: false })`로 기본값을 덮는다. 그래서 테스트에서는 `staleTime`이 0이 되어, 화면이 열릴 때 loader가 미리 불러온 목록을 한 번 더 조회한다. 무한 스크롤 테스트는 요청 순서 대신 offset 집합(0·20)으로 확인했다.
- 기존 공통 틀 E2E가 `navigation` 이름 "메뉴"를 부분 일치로 찾았다. 그래서 이번에 생긴 "하단 메뉴"까지 잡혔다. `exact: true`로 고치고 하단 탭이 보이는지 확인을 더했다.
- Shiki는 언어·테마마다 청크를 만든다(dist 약 15MB, 파일 600여 개). 코드 블록이 있을 때 그 언어만 받는다.
  - 초기 JS: 227kB(gzip 72kB). FE-1a 기록의 225kB와 거의 같다.
  - 마크다운(react-markdown·GFM): 상세 화면 청크(148kB, gzip 44kB)에 있다.
