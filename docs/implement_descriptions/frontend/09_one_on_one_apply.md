### 화면 규칙 (F30)
- 진행 시간 선택지는 진행 단위의 배수이고 120분까지이며 남은 1:1 시간 이하만 나온다. 진행 시간을 바꾸면 고른 희망 일시를 비운다(길이가 달라진다).
- 시간 칸은 고른 진행 시간으로 시작할 수 있는 30분 경계 시각만 보여 준다.
  - 이미 고른 시간과 겹치거나 3개를 고르면 다른 칸은 누를 수 없다.
  - 다시 누르면 빠진다.
- 멘토를 바꾸면 희망 일시를 비운다.
- 첫머리 판정(F28): 남은 시간이 없으면 멘토 목록은 보여 주되 [다음]을 막는다. 나머지 사유는 안내만 보여 준다. 다른 단계 주소로 들어와도 첫 단계로 보낸다.
- 대기 신청 최대 건수는 첫머리에서 판정하지 않는다. [신청하기]의 서버 오류 `too_many_pending_requests`로 알린다.
- 희망 일시·진행 시간·멘토 관련 서버 오류에는 '일정 다시 고르기' / '멘토 다시 고르기'를 함께 보여 준다.
- 완료되면 `step=done&id=`로 옮긴 뒤 임시 값을 지운다. [내 신청 보기]는 그 신청 상세로 간다.

### 제외한 범위 밖 요소 (F15)
- 시안 사이드바의 아직 없는 메뉴, 상단 기수 선택, 알림 종, '신청 내역' 건수 배지
- 시안 모달 뒤의 '이름·분야 검색' 입력

## 주요 결정 (사용자 결정, F30)
- 주소 `/mentoring/apply?step=`
- 가능한 시작 시각만 칸으로 보여 준다.
- 대기 한도는 서버 오류로만 알린다.
- 남은 시간 판정은 진행 단위와 비교한다.
- 전문 분야는 쉼표로 나눠 칩으로 보여 준다.
- 완료 후에는 신청 상세로 간다.
- 진입: 1:1만 → 1:1, 팀만 → 팀, 둘 다 → 종류 선택. FE-3a·FE-3b는 연달아 병합한다.
- 모바일 단계 표시는 두 줄이다.
- 달력은 shadcn Calendar(react-day-picker)로 만든다.

## 발견한 문제와 해결
- 신청이 성공하자마자 임시 값을 지웠더니, 화면이 바뀌기 전에 '앞 단계 값 없음' 판정이 첫 단계로 되돌렸다. 완료 화면으로 옮긴(`await navigate`) 뒤에 지우도록 바꿨다.
- 시안처럼 글자 수를 라벨 안에 넣었더니 입력 칸 이름이 '주제 8 / 100'이 됐다. 라벨과 글자 수를 나눴다.
- 공통 틀이 기수 설정 요약을 조회하게 되어, 테스트 기본 핸들러(`resetAuth`)에 설정 요약을 넣었다. 기본값은 1:1·팀 모두 허용이라 메뉴가 생기지 않는다.
- E2E에서 하단 탭 '신청'이 '신청 내역'과 부분 일치해 `exact: true`로 찾는다.
- **CI(UTC)에서 달 조회 범위가 비었다.** 달력의 달(TZDate)을 브라우저 시간대로 읽고 있었고, `new Date(tzDate)`가 문자열을 거쳐 바뀌어 한국 밖에서는 하루가 어긋났다. 실제 브라우저에서도 한국 밖이면 날 버그였다.
  - 날짜 키는 `Intl.DateTimeFormat`(Asia/Seoul)으로, 조회 범위는 KST 날짜 문자열과 일수로 계산하도록 바꿨다. 한국 밖이면 반복이 끝나지 않을 수 있던 계산도 없앴다.
  - `formatKst`는 Date를 `getTime()`으로 읽는다(`toEpochMs`).
  - 단위 테스트는 UTC·LA·서울 세 시간대에서 돌렸다. E2E 신청 흐름은 LA 시간대 브라우저로 돌린다.
  - jsdom에서 가짜 시계(Date)와 TZDate가 겹치면 한국 밖 시간대에서 시각 표시가 어긋나는 현상도 있었다. 실제 브라우저(UTC·LA E2E)에서는 생기지 않았다. 그래서 전체 흐름 테스트만 실제 시계와 이틀 뒤 일정으로 바꿨다.
- 긴 흐름 테스트가 CI에서 5초를 넘겨 그 테스트만 제한을 20초로 늘렸다.
- shadcn CLI(`add calendar`)는 react-day-picker를 `@latest`로 넣고 `button.tsx`를 새로 만들려 했다. CLI를 쓰지 않고 정확한 버전(10.0.2)을 설치한 뒤 Figma Calendar에 맞춘 얇은 래퍼를 직접 썼다.
