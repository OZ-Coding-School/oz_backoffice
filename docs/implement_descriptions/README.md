# 구현 기록 양식

기능 구현이 끝나면 같은 PR에서 구현 기록을 남긴다. (규칙: 루트 `README.md`의 "구현 기록")

- 위치: `backend/` (백엔드·저장소 공통 작업), `frontend/` (프론트엔드·Vercel 배포)
- 파일: `NN_<작업명>.md`. 해당 디렉터리의 마지막 번호 다음 번호로 만들고, 디렉터리 `README.md` 목록에 한 줄 추가한다.
- 이미 작성된 기록은 바꾸지 않는다. 같은 기능을 다시 고치면 새 번호로 기록하고 이전 기록을 링크한다. (상태 갱신은 예외)

## 양식

```markdown
# NN. <작업명>

- 상태: PR 진행 중 | 완료
- 관련 PR: #번호 (없으면 "PR 전")
- 관련 계획: docs/implement_plans/<문서>.md

## 배경
왜 이 작업을 했는지.

## 구현 내용
무엇을 만들었는지. 주요 파일 경로와 역할.

## 주요 결정
구현 중 내린 결정과 이유. 사용자가 결정한 것은 "(사용자 결정)"으로 표시하고 docs/decisions.md 항목 번호를 적는다.

## 발견한 문제와 해결
작업 중 만난 문제, 원인, 해결 방법.

## 검증
실행한 검사와 결과 (린트, 타입, 테스트, 수동 확인). 실행하지 못한 검증은 이유와 함께 적는다.

## 남은 작업
후속으로 해야 할 일.
```
