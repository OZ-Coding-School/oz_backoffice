- 이전 기록: [72. 내 팀 응답 보완 (BE-2g)](72_my_team_summary.md)

## 배경
FE-7 채팅의 '새 대화'에서 상대를 고르는 목록을 확인하다가 문제가 나왔다. 수강생에게는 '신청 받는 멘토' 목록만 있었고, 멘토에게는 담당 수강생 목록 API가 없었다. 사용자는 정책을 바꾸기로 했다. 채팅은 **신청 이력이 있는 상대와만** 하고, 방은 신청 안내 메시지로 생기므로 새 대화 버튼을 두지 않는다(A74).

## 구현 내용

| 파일 | 바꾼 것 |
| --- | --- |
| `mentoring/application/chat_service.py` | 자격을 활성 배정·수강 중·현재 담당 멘토 대신 **신청 이력**(`ChatHistory.chat_pairs`)으로 판정. 팀 방 참여자는 지금 팀원 |
| `mentoring/infrastructure/repositories.py` | `TortoiseMentoringRequestRepository.chat_pairs`: (멘토, 1:1 수강 등록 또는 팀), 상태 무관, 중복 제거 |
| `mentoring/presentation/notices.py`, `workers/tasks/mentoring.py` | 채팅 서비스 조립을 배정 저장소 대신 신청 저장소로 |
| `tests/fakes/mentoring.py` | 인메모리 신청 저장소에 `chat_pairs` |

API 형태는 바뀌지 않았다(생성 타입 변경 없음).

## 주요 결정 (사용자 결정, A74)
- 신청 이력은 상태 무관 1건 이상이다. 1:1은 본인 신청, 팀은 팀 신청이 기준이다.
- 수강 상태·배정·팀의 현재 담당 멘토는 보지 않는다. 수강생과 멘토가 같은 기준이다.
- 새 대화 버튼은 두지 않는다.

## 발견한 문제와 해결
- 반려·취소 신청을 직접 넣으면 DB CHECK(사유·시각 필수)에 걸려, 통합 테스트는 승인·대기로 상태 무관을 확인했다. 단위 테스트는 반려 신청으로 확인했다.

## 검증
- 단위
  - 반려 신청 이력으로 대화 시작
  - 이력이 없으면 거부(멘토 쪽도)
  - 수강 종료·배정 종료 뒤에도 방 유지
  - 팀: 1:1 이력은 팀 자격이 아님, 담당 멘토가 바뀌어도 이전 방 유지, 새 멘토는 팀 신청 뒤에만, 팀에서 빠지면 숨김
  - 안내: 이력이 없는 방은 알리지 않음
- 통합: `chat_pairs`(상태 무관, 1:1·팀, 빈 입력)
- API: 채팅 흐름 테스트를 신청 이력이 있는 상태로 맞춤
- **로컬 검사 (compose `api`):** ruff, ruff format, mypy, mypy tests, lint-imports 통과. 전체 898 passed.
- 생성 타입 변경 없음(프론트 `typecheck` 통과)
- **CI:** 통과. 사용자가 병합을 확인했다(2026-11-20)
