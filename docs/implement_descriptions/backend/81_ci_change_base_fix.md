# 81. CI 변경 감지: 이전 커밋이 통과했을 때만 건너뛰기

- 상태: PR 진행 중
- 관련 PR: (작성 중)
- 관련 결정: `docs/decisions.md` R9 (보완)
- 이전 기록: [80. CI 시간 줄이기](80_ci_speedup.md)

## 배경
R9(#121)에서 PR에 커밋을 이어 올리면 이전 head와 비교하고, 문서만 바뀌면 검사를 건너뛰게 했다. #122(FE-12b)에서 기능 커밋을 올린 직후 PR 번호 기록 커밋을 올리자 문제가 생겼다. 새 push가 기능 커밋의 실행을 취소했고(같은 concurrency 그룹), 새 실행은 문서만 바뀌었다고 판단해 모든 검사를 건너뛰었다. 그대로였으면 검사하지 않은 코드가 '통과'로 보였을 것이다. 취소된 실행을 다시 돌려 #122의 코드는 확인했다.

## 구현 내용

| 파일 | 바꾼 것 |
| --- | --- |
| `.github/workflows/ci.yml` | `actions: read` 권한. 변경 감지에서 이전 head의 이 워크플로 실행 중 성공한 것이 있을 때만 이전 head와 비교한다. 없으면 PR은 develop과 갈라진 지점부터, main·develop push는 전체 검사 |

- 조회는 `gh api repos/{repo}/actions/runs?head_sha=`이다. 실패하면 '통과 아님'으로 보고 넓게 검사한다.

## 검증
- actionlint: 새 경고 없음
- 조회 함수를 로컬에서 실제 커밋으로 확인했다: 다시 돌려 통과한 커밋 → 통과, 취소된 커밋·0 → 통과 아님
