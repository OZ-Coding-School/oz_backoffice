## 배경
P12-2를 실제 Google로 테스트하다가, 자동 녹화·전사·메모가 **주최자나 공동 주최자가 웹으로 들어와야 시작된다**는 것을 확인했다(Google Meet 도움말, 2026-11-13 실제 확인). 공간 주최자는 `GMAIL_SENDER`라 실제 멘토링(멘토·수강생만 참여)에서는 녹화가 시작되지 않는다. 담당 멘토를 공동 주최자로 등록해 해결한다(A52).

## 실제 확인한 것 (2026-11-13, 테스트 공간)
1. 주최 계정 혼자 입장 → 녹화됨.
2. Workspace가 아닌 Gmail 계정 혼자 입장 → **녹화 안 됨**.
3. 그 Gmail을 Meet API로 공동 주최자(COHOST) 등록 → 입장 시 **외부 방문자로 표시**, 녹화 안 됨. 공간의 주최자 관리(moderation)가 꺼져 있으면 공동 주최자 역할이 적용되지 않는다.
4. 주최자 관리를 켬 → 같은 계정이 **공동 주최자로 표시되고 자동 녹화가 시작**됨.
5. 이 PR의 코드로 새 공간을 만들어 확인: 입장 OPEN, 주최자 관리 ON, 자동 녹화 ON, 멤버 COHOST. 테스트 공간 두 개는 입장 제한(RESTRICTED)으로 막았다.

## 주요 결정 (사용자 결정, A52)
- 멘토를 공동 주최자로 등록하고, 이를 위해 공간의 주최자 관리를 켠다.
- 공동 주최자 이메일은 **멘토의 가입 이메일**이다. 멘토는 그 이메일의 Google 계정으로 로그인해 웹으로 들어와야 녹화된다.

## 발견한 문제와 해결
- **테스트가 실제 Google을 호출:** 로컬 `.env`에 `MEET_DRIVER=google`을 넣자 작업 코드(`get_settings()`로 `.env`를 읽음)를 부르는 테스트가 실제 Google을 호출했다(전체 실행 21초 → 60초). 테스트 전체에서 개발용 드라이버를 환경 변수로 강제하고 설정 캐시를 비우는 autouse 픽스처를 추가했다. CI에는 `.env`가 없어 영향이 없었다.

## 운영 안내 (멘토)
- 멘토링 Meet에는 **가입 이메일과 같은 Google 계정으로 로그인한 웹 브라우저**로 들어와야 공동 주최자가 되고 녹화가 시작된다. 가입 이메일이 Google 계정이 아니면 녹화되지 않는다. 멘토 안내 문구는 프론트엔드·알림(M24) 작업 때 넣는다.
- 공동 주최자는 회의에서 참가자를 내보내거나 음소거할 수 있다(주최자 관리 권한).
