## 배경
멘토링 1단계의 마지막 기능인 채팅(P15)의 첫 PR이다. 기존 mentor 서비스는 수강생-멘토 1:1 채팅(Firestore 실시간, 최신 50개 + 커서, 화면을 볼 때 읽음)과 예약 안내 메시지를 제공했다. 이 PR은 REST로 채팅방·메시지·삭제·읽음·운영진 열람을 만들고, 실시간 수신(SSE)과 멘토링 이벤트 안내 메시지는 P15-2에서 붙인다(A57).

**API**

| 대상 | 경로 |
| --- | --- |
| 참여자(수강생·멘토) | `GET /api/v1/me/mentoring/chat/threads` (마지막 메시지 최신순, 안 읽음 수·마지막 메시지 포함) |
| | `POST /api/v1/mentoring/chat/messages` (상대를 골라 보내기, 방이 없으면 만듦: `team_id` / 수강생은 `cohort_id`+`mentor_id` / 멘토는 `student_id`) |
| | `GET /api/v1/mentoring/chat/threads/{id}`, `GET .../{id}/messages?before=&limit=` (최신부터, 기본 50, 최대 100, `next_before` 커서) |
| | `POST .../{id}/messages`, `DELETE .../{id}/messages/{message_id}`, `PUT .../{id}/read` (`message_id`) |
| 운영진(`mentoring.request.read`, 기수 범위, 열람만) | `GET /api/v1/admin/cohorts/{cohort_id}/mentoring/chat/threads?mentor_id=`, `.../{id}`, `.../{id}/messages` |

**스키마 (DBML 반영)**
- `mentoring_chat_threads`: `num_nonnulls(student_id, team_id) = 1`, `(student_id, mentor_id)`·`(team_id, mentor_id)` 부분 유니크.
- `mentoring_chat_messages`: `body`를 null 허용으로 바꾸고 `deleted_at` 추가. check 3개(본문 1~2,000자, 지웠으면 본문 없음·남았으면 본문 있음, 안내 메시지는 지우지 않음). 인덱스를 `(thread_id, created_at)`에서 커서용 `(thread_id, id)`로 바꿨다.
- `mentoring_chat_reads`: Tortoise가 복합 PK를 지원하지 않아 **모델 없이** 마이그레이션 raw SQL로 만들고 리포지토리가 SQL로 다룬다(테스트의 TRUNCATE는 CASCADE로 함께 비워진다).

## 주요 결정 (사용자 결정, A57)
- 실시간 전송은 **SSE 수신 + REST 전송**, 사용자당 연결 하나(B7 확정, P15-2).
- 메시지는 **텍스트 2,000자**, 수정 없음. **본인 메시지는 기한 없이 삭제**(본문을 비우고 '삭제된 메시지'로 표시, 운영진에게도 같음). 안내 메시지는 삭제 불가.
- **1:1 방은 처음 메시지를 보낼 때 자동으로** 만들고, 수강생·멘토 누구나 먼저 시작한다.
- **참여 자격**: 1:1은 수강생이 수강 중이고 그 기수에 그 멘토의 활성 배정이 있을 때, 팀은 현재 팀원이고 팀의 현재 담당 멘토가 방의 멘토일 때. 자격이 없어지면 **목록에서 숨김**(단건은 404). 팀 담당 멘토가 바뀌면 새 방이 생긴다.
- **운영진은 기수 범위에서 열람만**.
- 읽음은 클라이언트가 본 마지막 메시지 ID를 보내 **앞으로만** 옮기고, 안 읽음 수는 그 뒤 **남이 보낸 메시지(안내 포함, 삭제 제외)** 수.
- 안내 메시지(신청·승인·반려, 취소·변경, 기록 제출)와 SSE는 P15-2. 새 메시지 메일 알림은 알림 방식(M24) 결정 때.

## 구현 세부
- **자격이 없으면 404:** 계획 문서의 "참여자 아닌 사용자 403" 대신, 세션 조회(A43)와 같이 방의 존재를 숨기는 404 `chat_thread_not_found`로 했다. 다른 방의 메시지 ID로 삭제·읽음을 요청하면 404 `chat_message_not_found`.
- **보내면 내 읽음 위치도 옮긴다:** 보낸 사람은 그 메시지까지 본 것으로 둔다(보낸 뒤 내 안 읽음 수 0).
- **방 생성:** `INSERT … ON CONFLICT DO NOTHING` 뒤 다시 읽어 동시에 처음 보내도 방이 하나다. 본문 검사를 먼저 해서 잘못된 메시지로 빈 방이 생기지 않는다. 방 생성과 첫 메시지는 한 트랜잭션이다.
- **정렬:** 방 목록은 `COALESCE(last_message_at, created_at)` 최신순. 운영진 목록은 수강 등록·팀을 조인해야 해서 SQL로 id만 골라 읽는다(조인 쿼리에 정렬식을 붙이면 Tortoise가 컬럼 이름을 한정하지 않아 `created_at`이 모호해진다).
- **읽음 upsert:** SQL에서도 `last_read_message_id`가 더 클 때만 바꿔 동시 요청에도 뒤로 가지 않는다. uuid7이라 ID 순서가 시간 순서다.
- **참여자 목록:** 후보 방(내 수강 등록·팀·멘토 프로필)을 읽은 뒤 자격을 걸러 페이지를 자른다. 한 사람이 참여하는 방 수가 적어 메모리에서 거른다.
- **조회 수:** 방 목록은 수강 등록·멘토·팀·후보 방·수강생·팀·배정(방의 멘토마다 1회)·마지막 메시지(2)·안 읽음 수(1)와 이름 붙이기(수강생·팀·멘토·회원)로, 방 수와 무관하다(배정만 방의 멘토 수만큼). 메시지 목록은 방 1 + 메시지 1 + 이름 3.
